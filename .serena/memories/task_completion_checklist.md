# タスク完了時のチェックリスト

## コード変更後の必須手順

### 1. Lint実行
```bash
cd frontend
pnpm lint
```
- エラーがないことを確認
- 警告も0にする（max-warnings 0設定）

### 2. TypeScriptコンパイル確認
```bash
cd frontend
pnpm build
```
- 型エラーがないことを確認

### 3. テスト実行（該当する場合）

#### Moveコントラクト
```bash
cd contract
sui move test
```

#### フロントエンド
- 現在テストフレームワークは未設定
- 将来的にはVitest等を導入予定

### 4. コードレビュー自己チェック

#### セキュリティ
- [ ] APIキー、パスワード等は環境変数で管理
- [ ] すべての外部入力を検証
- [ ] 最小権限の原則に従っている

#### エラーハンドリング
- [ ] エラーケースを適切に処理
- [ ] try-catchで握りつぶしていない
- [ ] 明確なエラーメッセージを提供

#### コード品質
- [ ] DRY原則に従っている
- [ ] 意味のある変数名・関数名を使用
- [ ] 不要なコードを削除
- [ ] コメントで「なぜ」を説明

#### パフォーマンス
- [ ] 不要な再レンダリングを避ける
- [ ] 必要に応じて遅延読み込みを実装
- [ ] N+1問題を回避

### 5. Git操作

#### コミット前
```bash
git status
git diff
```

#### コミット（コンベンショナルコミット形式）
```bash
git add .
git commit -m "feat: 機能の説明"
```

#### プッシュ前
- [ ] コミットメッセージが明確
- [ ] 1つのコミットに1つの変更
- [ ] 英語で記述

### 6. ドキュメント更新

- [ ] READMEの更新（必要な場合）
- [ ] 重要な設計判断をADRで記録（必要な場合）
- [ ] コードコメントの更新
